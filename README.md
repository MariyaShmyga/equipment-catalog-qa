# Каталог оборудования: API, SQLite и автотесты

Небольшое веб-приложение для тренировки QA/AQA. Каталог импровизированный — он не связан с реальными поставщиками, а заявки никуда не отправляются. Суть проекта в том, чтобы можно было проследить весь путь данных: CSV → SQLite → API → интерфейс → заявка в базе.

Каталог содержит **48 товаров в шести категориях**. Данные хранятся в SQLite, начальный набор загружается из CSV и JSON. Повторный старт не очищает таблицу заявок. Можно искать оборудование, применять фильтры и оставлять заявки. Заявки сохраняются локально, без отправки во внешние сервисы.

## Что проверяется

### API — Pytest и FastAPI TestClient

- Получение списка товаров и карточек отдельных товаров.
- Поиск по названию без учёта регистра, включая обработку символов `%` и `_`.
- Фильтрация по категории, цене и наличию.
- Сортировка, лимит и смещение результатов.
- Валидация параметров и ответы на некорректные запросы.
- Создание заявки: обязательные поля, существование товара и доступный остаток.

### База данных — Pytest и SQLite

- Импорт категорий и товаров из JSON/CSV.
- Ограничения `FOREIGN KEY` и `CHECK`.
- Сохранение заявок в таблице `quotes`.
- Повторная инициализация БД без потери уже записанных заявок.
- Независимость тестов друг от друга за счёт временных баз.

### Интерфейс — Playwright и Chromium

- Первичная загрузка каталога и кнопка «Показать ещё».
- Поиск, фильтры и сортировка.
- Отправка заявки из формы с проверкой записи в SQLite.
- HTML-валидация email.
- Реакция интерфейса на ошибку API `503`.

**Всего 94 автоматизированные проверки: 85 API/DB и 9 UI.** Это число не следует трактовать как процент покрытия: авторизация, платежи и внешние интеграции в приложении не реализованы.

## Локальный запуск

Требуется **Python 3.11+**. Пример ниже — для Windows и PowerShell. Все команды выполняются из корня проекта, рядом с `requirements.txt`.

### 1. Установка зависимостей

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m playwright install chromium
```

### 2. Запуск тестов

Все тесты:

```powershell
.\.venv\Scripts\python.exe -m pytest -q
```

Только API и БД:

```powershell
.\.venv\Scripts\python.exe -m pytest tests/test_api.py tests/test_database.py -q
```

Только UI:

```powershell
.\.venv\Scripts\python.exe -m pytest tests/test_ui.py -q
```

Для краткого вывода ошибок можно добавить `--tb=short`.

### 3. Запуск приложения

```powershell
.\.venv\Scripts\python.exe -m uvicorn catalog.main:app --reload
```

После запуска доступны:

- [Веб-интерфейс](http://127.0.0.1:8000)
- [Swagger UI](http://127.0.0.1:8000/docs)

При первом запуске создаётся `data/catalog.sqlite3` с исходными категориями и товарами. Для полного сброса локальных данных нужно остановить сервер, удалить этот файл и снова запустить приложение. **При сбросе удаляются и сохранённые заявки.**

## Как организованы тесты

**Изоляция данных.** API-тесты работают с отдельными временными базами SQLite, которые создаются через фикстуры Pytest. Таким образом, заявка из одного теста не влияет на результаты другого.

**Проверка записи.** При оформлении заявки проверяется не только статус HTTP `201`, но и наличие соответствующей строки в таблице `quotes`.

**Браузерные сценарии.** Для UI-тестов запускается локальный HTTP-сервер с собственной тестовой БД. Playwright работает через браузер; элементы ищутся по `data-testid`, чтобы тесты меньше зависели от CSS-классов и текста кнопок. Отдельный сценарий проверяет отображение ошибки при ответе API `503`.

**CI.** В `.github/workflows/tests.yml` настроен запуск проверок для изменений в репозитории. Workflow устанавливает зависимости и Chromium, после чего выполняет тесты. Состояние последнего запуска можно посмотреть во вкладке **Actions** репозитория.

Дополнительные сценарии и обоснование технических решений описаны в [`docs/checks.md`](docs/checks.md) и [`docs/decisions.md`](docs/decisions.md).
