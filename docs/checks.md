# Какие сценарии я проверяю

Начала с пользовательского пути: найти нужное оборудование, уточнить наличие, оставить запрос предложения. Самое неприятное в таком сервисе — ситуация, когда интерфейс обещает «заявка отправлена», а в базе ничего нет. Поэтому проверка записи в `quotes` для меня важнее, чем отдельный тест на цвет кнопки.

| Участок | Что проверять | Автоматизация |
| --- | --- | --- |
| Каталог | 48 записей из CSV, уникальные SKU, корректная схема ответа | `test_api.py` |
| Поиск | разный регистр, пробелы, пустой результат, `%`, `_`, строка с SQL-кодом | `test_api.py` + `test_ui.py` |
| Фильтры | каждая категория, наличие, диапазон цен, сочетания условий | `test_api.py` |
| Выдача | порядок сортировки, первые 12 и следующие 12, большой offset | `test_api.py` + `test_ui.py` |
| Карточка | существующий и отсутствующий ID, нечисловой ID | `test_api.py` |
| Заявка | корректный запрос сохраняется, повторные заявки имеют разные ID | `test_api.py` + `test_ui.py` |
| Валидация | пустые/длинные поля, email, 0/101 единица, лишний параметр | `test_api.py` |
| Остатки | товара нет, остатка недостаточно, товар не существует | `test_api.py` |
| Сама БД | внешние ключи, CHECK, сохранность заявки после перезапуска | `test_database.py` |
| Ошибка API | интерфейс не оставляет пользователя перед пустым экраном | `test_ui.py` |

## Что стоит проверить руками

Это **список для проверки**, а не отчёт о выполненной работе. Я не ставлю галочки там, где ещё не воспроизводила сценарий.

- [ ] Открыть интерфейс на ширине 375 px. Все поля формы доступны, горизонтальной прокрутки нет.
- [ ] При медленном соединении быстро менять поисковую строку. В итоге должен остаться результат последнего запроса.
- [ ] После выбора карточки убедиться, что в форме подставился именно этот товар.
- [ ] Проверить переход по Tab: порядок фокуса по фильтрам, карточкам и форме.
- [ ] Отключить сервер во время отправки заявки. Должно появиться понятное сообщение о недоступности.
- [ ] Указать количество больше остатка. API возвращает 409, интерфейс объясняет причину.
- [ ] Проверить, что заявка переживает перезапуск приложения и повторная загрузка seed не создаёт дубликатов.

## Пока не покрыто

Нет авторизации и ролей, истории статусов заявки, конкурирующих заказов и списания остатков. Нет нагрузочного тестирования, визуальной регрессии и тестирования доступности со скринридером. Запрос предложения не резервирует товар, поэтому несколько заявок на одну и ту же позицию допустимы — см. `decisions.md`.
