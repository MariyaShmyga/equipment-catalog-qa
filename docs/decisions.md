# Пара замечаний по реализации

**Почему SQLite, а не PostgreSQL?** Для этого стенда важнее, чтобы тесты можно было запустить одной командой даже на новом ноутбуке. SQLite здесь не «список в памяти»: есть три связанные таблицы, внешние ключи, ограничения и транзакция при создании заявки. Для API-тестов отдельная БД создаётся прямо в `tmp_path` Pytest. С PostgreSQL пришлось бы дополнительно поднимать сервис и чистить записи между тестами. При необходимости этот стенд можно перевести на PostgreSQL, но сначала хочется надёжного набора проверок.

**Зачем одновременно CSV и JSON?** Товарные строки удобно редактировать в таблице — поэтому `products.csv`. Категории занимают всего шесть записей, у каждой короткий ключ и русское название — для этого оставила JSON. Во время запуска импорт выполняется только для отсутствующих записей, так что заявки не пропадают из-за перезапуска.

**Почему запрос не уменьшает остаток?** Это не покупка и не бронь. Клиент просит коммерческое предложение, а менеджер потом уточняет наличие. Мы отклоняем запрос на количество выше остатка, но не списываем товары. Для настоящей системы это требование нужно согласовывать с бизнесом: вполне возможно, под заказ надо позволять отправлять запрос и при нулевом остатке. Здесь выбран более жёсткий сценарий, чтобы была проверяемая бизнес-ошибка 409.

**Где риск ложных срабатываний?** Если тесты делят одну базу и одновременно создают заявки, ID и количество строк начинают зависеть от порядка запуска. Поэтому API-тесты полностью изолированы, а UI использует отдельный файл базы на тестовую сессию. Для проверок формы я ищу сохранённую запись по конкретному адресу, а не рассчитываю, что заявка всегда будет первой.

**Что дальше?** Если останется время, хочу добавить в API получение деталей заявки с доступом по роли, обновление её статуса и набор проверок 401/403. Просто открывать GET на все заявки без авторизации неправильно: там есть контактные данные.

## Посмотреть записи без интерфейса

После отправки заявки через браузер можно выполнить эти запросы в SQLite Viewer или SQLite Explorer. Так видно, что данные действительно сохраняются, а не просто возвращаются из Python-словаря:

```sql
-- Товары по категориям, включая отсутствующие на складе
SELECT c.title, COUNT(*) AS product_count,
       SUM(CASE WHEN p.stock = 0 THEN 1 ELSE 0 END) AS out_of_stock
FROM categories AS c
JOIN products AS p ON p.category_slug = c.slug
GROUP BY c.slug, c.title
ORDER BY c.title;

-- Недавние заявки вместе с товаром
SELECT q.id, q.customer_name, p.sku, p.name,
       q.quantity, q.status, q.created_at
FROM quotes AS q
JOIN products AS p ON q.product_id = p.id
ORDER BY q.id DESC
LIMIT 10;
```
